# 0007. XLSX·PPTX 지원 방식 (데스크톱·모바일)

- 상태: **보류 (2026-11-05)** — 사용자가 더 연구한 뒤 정한다. v0.3.0 은 XLSX·PPTX 없이 낸다(제안 2026-11-04, 아래 "정할 것")
- 관련: [formats/README.md](../formats/README.md), [0004 HWP 엔진](0004-hwp-engine.md), [0006 모바일 연결](0006-mobile-bridge.md)

## 맥락

지금 엔진과 두 앱은 **쪽(page) 모델**이다. `Document` 가 쪽 수·쪽 크기·쪽 그리기(비트맵)·글자·찾기·목차를 주고,
데스크톱(`PageCanvas` + 그리기 대기열)과 모바일(플랫폼 화면이 비트맵을 그림, ADR 0006)은 형식을 모른 채 쪽을 그린다.
DOCX 는 rhwp 문서 구조로 바꿔서(`papy-office`) 이 길을 그대로 탔고, 덕분에 앱 코드 없이 보기·편집·PDF 내보내기가 됐다.

- **PPTX** 는 슬라이드 = 쪽이라 이 모델에 맞는다.
- **XLSX** 는 맞지 않는다. 쪽이 없고, 크기가 정해지지 않은 격자다. 열 너비·행 높이, 틀 고정, 병합 칸, 시트 탭, 수식이 있다.
  "인쇄 쪽"으로 나누면 넓은 표가 여러 쪽으로 쪼개져서 보기가 나쁘다.

## 제안

### PPTX — 슬라이드를 rhwp 문서로 바꿔 지금의 쪽 길을 탄다 (DOCX 와 같은 방식)

1. `papy-office` 에 `pptx_to_document`: 슬라이드 하나 = 한 쪽(쪽 크기 = 슬라이드 크기), 도형은 쪽 기준 절대 위치 개체로 옮긴다.
   - 글상자·사각형·타원·선·그림·표는 DOCX 도형 변환(`shapes.rs`)과 표·그림 코드를 다시 쓴다.
   - 마스터·레이아웃 상속(자리표시자 위치·글꼴·테마 색), 글머리표, 배경 색·그림은 PPTX 쪽에서 풀어서 넣는다.
   - 차트·SmartArt·그라데이션·효과·애니메이션·동영상은 옮기지 않고 `dropped_objects` 로 센다(앱이 이미 알린다).
2. 1단계는 **보기 전용**: 저장 형식은 PDF·텍스트만(HWP 3.x 와 같은 처리). PPTX 다시 쓰기는 손실이 커서 뒤로 미룬다.
3. 얻는 것: 썸네일·확대·글자 보기·찾기·PDF 내보내기, 그리고 **앱 코드 거의 없이** 데스크톱·모바일 둘 다.
   - 데스크톱: 여는 확장자(`OPENABLE`)·파일 연결·대화상자 필터에 `.pptx` 를 더한다.
   - 모바일: 파일 고르기 MIME, Android intent-filter·iOS UTType, `DocumentSummary.format` 에 `"pptx"` 를 더한다. 쪽 화면은 그대로 쓴다.
4. 위험(PoC 로 확인): rhwp 가 한 쪽에 떠 있는 개체 수십 개, 슬라이드 크기(16:9) 쪽, 글상자 글자 자동 맞춤을 견디는가.
   충실도가 모자라면 2안(아래)으로 간다. 이 경우에도 `Document` 계약은 같아서 앱은 바뀌지 않는다.

대안:

| 안 | 장점 | 단점 |
|---|---|---|
| **1. rhwp 문서로 변환(제안)** | 기존 그리기·글꼴·PDF·찾기·모바일 그대로. 가장 빠름 | 슬라이드 전용 표현(테마·효과·자동 맞춤)이 rhwp 모델 밖이면 근사치 |
| 2. 자체 DrawingML → SVG → resvg | 이미 쓰는 resvg/usvg·fontdb 재사용, 충실도 상한이 높음 | 글자 배치(줄바꿈·자동 맞춤·한글 조판)를 새로 만들어야 함. 일이 큼 |
| 3. 외부 crate(deckcraft-render, document-svg 등) | 바로 써 볼 수 있음 | 아직 젊고 라이선스·유지보수·한글 품질 미확인. PoC 비교 대상으로만 |
| 4. LibreOffice 변환 | 충실도 높음 | 수백 MB, 모바일 불가, 오프라인 단일 앱 원칙과 안 맞음 → 제외 |

### XLSX — 새 "시트" 모델 + 엔진이 그리는 격자 조각(tile)

1. **엔진(`papy-sheet`, 새 crate)**: 1순위 [IronCalc](https://github.com/ironcalc/IronCalc)(Rust, MIT/Apache-2.0, xlsx 읽기·쓰기, 수식 계산).
   아직 0.x 이고 차트·그림·조건부 서식은 약하다. 비교 대상은 calamine(빠른 읽기 전용, 서식 거의 없음; 서식은 calamine-styles 포크).
   **보기만이면 calamine 도 되지만, 편집·저장·다시 계산까지 갈 거면 IronCalc** 가 맞다 → PoC 로 같은 문서 모음에서 견준다.
2. **엔진 API**: `Document` 와 나란히 `Workbook` 계약을 둔다.
   - `sheets()`(이름·크기·틀 고정), `col_widths/row_heights`, `cells(sheet, 행 범위, 열 범위)`(표시 글자 = 서식 적용 값, 스타일, 병합)
   - `render_tile(sheet, x, y, w, h, scale)` → 비트맵. 격자·테두리·채우기·글자를 tiny-skia(+ 지금의 글꼴)로 엔진이 그린다.
   - `hit_test(sheet, x, y) → (행, 열)`, `find_text`, 나중에 `set_cell`(값·수식)·되돌리기·저장.
   - PDF 내보내기·썸네일용으로 "인쇄 쪽"(`Document`) 도 따로 준다(인쇄 영역·쪽 나누기 반영은 2단계).
3. **그리기를 엔진에 두는 이유**: 격자와 한글 글자를 두 플랫폼(데스크톱 웹, Android Compose, iOS SwiftUI)에서
   세 번 따로 그리면 모양이 달라지고 일이 세 배다. 모바일은 이미 "비트맵 받아 확대·다시 그리기" 길이 있어서 조각만 바꿔 끼우면 된다.
4. **앱 화면**(형식별로 새로 만들어야 하는 유일한 부분):
   - 데스크톱: 시트 탭, 행·열 머리글, 틀 고정, 스크롤하면 보이는 조각만 그리기(지금 그리기 대기열 재사용), 칸 선택·복사(`cells` 로 TSV).
     2단계: 수식 입력줄·칸 편집.
   - 모바일: 같은 조각 화면(두 손가락 확대·이동), 시트 고르기, 칸 누르면 값·수식 보기. 편집은 칸 하나 고치기부터.
5. DOCX 처럼 rhwp 표로 바꾸는 길은 **택하지 않는다**: 열·행이 많으면 쪽이 쪼개지고, 수식·시트·틀 고정을 잃는다.

## 순서(제안)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 0 | 공개 시험 문서 모음: Apache POI test-data(Apache-2.0)의 xlsx·pptx, 자체 생성 문서 | `tests/README.md` 출처 기록, 문서 모음 회귀(`corpus.rs`)에 넣기 |
| 1 | PPTX 보기 PoC(1안) — 변환기 + 형식 판별(`ppt/presentation.xml`) | 문서 모음 실패 0, 슬라이드 쪽 수·글자 일치, 빠진 개체 수 표시 |
| 2 | XLSX 엔진 PoC — IronCalc vs calamine 비교(열기 시간·메모리·서식·수식 결과) | 엔진 선택 ADR 승인 |
| 3 | XLSX 보기: `Workbook` API + 조각 그리기 + 데스크톱 화면 | 데스크톱에서 시트 탭·스크롤·확대·복사·PDF 내보내기 |
| 4 | XLSX 모바일 화면(Android·iOS) + `papy-ffi` | 에뮬레이터·시뮬레이터 확인 |
| 5 | 편집: XLSX 칸 고치기·저장, PPTX 글상자 글자 고치기(필요하면) | 저장 → 다시 열기 왕복 테스트 |

형식 판별은 이미 "그 밖의 ZIP → Office 후보"까지 되어 있으니 `[Content_Types].xml` 이나 `xl/workbook.xml`·`ppt/presentation.xml` 유무로 나누기만 하면 된다.

## 정할 것

1. **순서**: 계획표 우선순위(XLSX P1)대로 XLSX 부터 갈지, 싸게 끝나는 PPTX 보기를 먼저 낼지. 제안: PPTX 보기 PoC 먼저(1~2주 규모), XLSX 엔진 PoC 를 나란히.
2. **XLSX 범위**: 1차를 보기 전용으로 할지(calamine 으로도 됨), 처음부터 편집을 목표로 할지(IronCalc).
3. **XLSX 그리기**: 엔진 조각 그리기(제안)인지, 플랫폼마다 네이티브 격자인지.
