# 0010. 한글·워드를 계열별로 다루고, 다른 계열로는 사용자가 고를 때만 바꾼다

- 상태: **승인 (2026-11-14)** — 사용자가 방향을 정했고("한글하고 DOC 파일 혼용은 무리야, 각각 엔진 대비하고 선택에 따라
  대응하는 게 맞을 것 같다"), 확인과 세부 결정은 맡겼다("너가 대신 확인하고 더 나은 방향으로 승인해줘").
- 관련: [0008 제품 순서와 엔진 구조](0008-product-order-and-engines.md)(2항 "엔진 구조"를 이 결정이 보탠다),
  [형식 변환 점검](../formats/test-corpus.md)

## 맥락

2026-11-14 Windows 점검(실제 Word 16·한컴 한글로 열어 봄, 시험지 12개와 누름틀 문서)에서 다음을 봤다.

- **같은 계열은 이미 원본과 가깝다.** Word 문서를 Papy 로 연 쪽 수는 Word 와 오차 3.7%(111개 중 100개 같음, 2026-11-08).
  한글 문서를 Papy 가 HWP·HWPX 로 저장하면 한글에서 26개 모두 열리고 쪽 수가 원본과 같았다.
- **계열을 건너면 크게 어긋난다.** 한글→DOCX 를 Word 로 열면 쪽 수 오차 평균 14~19%이고, 2단 시험지는 8 → 16쪽이 된다.
  이는 두 프로그램의 조판 규칙이 달라서 생긴다(ADR 0008 3항). 이날 고친 버그 3개(Word 가 못 여는 DOCX, 한글이 못 여는 HWP,
  쪽 수가 세 배가 되는 HWP)도 모두 계열을 건너는 변환에서 나왔다.
- **같은 형식 저장도 한글 모델을 거쳤다.** DOCX 를 열어 고치지 않고 DOCX 로 저장해도, rhwp(한글) 문서 모델에서 DOCX 를
  다시 만들었다. 그래서 Papy 가 옮기지 못하는 Word 요소(사용자 XML, 테마, 옮기지 못한 개체 등)가 그냥 저장만 해도 빠졌다.

사용자가 걱정한 "혼용"은 둘째와 셋째다. 조판(화면 그리기)을 형식마다 따로 만드는 것은 해법이 아니다. 계열을 건너는
어긋남은 형식 규칙이 달라서 생기므로 Word 조판 엔진을 새로 만들어도 줄지 않는다. 비용은 1인+AI 기준 보기만 6개월~1년이다(ADR 0008 표).

## 결정

1. **문서는 두 계열로 나눠 다룬다.**
   - 한글 계열(HWP·HWPX): rhwp 문서가 기준이다. 지금과 같다.
   - 워드 계열(DOC·DOCX): **원본 DOCX 파일이 기준**이다. rhwp 문서는 보여 주고 편집하는 데 쓰는 사본이다.
2. **화면 조판은 rhwp 하나로 둔다**(ADR 0008 2항 그대로). Word 조판 엔진을 따로 만들지 않는다.
3. **같은 계열로 저장할 때는 원본을 지킨다.**
   - 1단계(2026-11-14 적용): 고치지 않은 DOCX 를 DOCX 로 저장하면 원본 파일을 바이트 그대로 돌려준다.
     "고치지 않음"은 되돌리기·다시 하기 기록이 둘 다 비었는지로 본다. 모든 편집(글·칸·표·그림·서식, AI 적용 포함)은
     되돌리기 단계를 만든다. 되돌려 원래대로 돌아와도 다시 하기가 남아 있으면 다시 쓴다(원본을 잘못 돌려주는 쪽을 피한다).
   - 2단계(할 일): 고친 DOCX 는 원본 패키지에 **바뀐 부분만 다시 써 넣는다**. 손대지 않은 부분과 Papy 가 모르는 요소는 남긴다.
     그 전까지 고친 DOCX 는 지금처럼 다시 만든다.
   - 시험·점검 도구는 쓰기 경로를 보려고 `OpenOptions::rewrite_same_format` 을 켠다. 앱은 끈 채로 둔다.
4. **다른 계열로는 사용자가 고를 때만 바꾼다.** 앱의 기본 저장 형식은 연 형식이다(옛 DOC 는 DOCX). 다른 계열로 저장하거나
   내보낼 때는 지금처럼 변환 오차를 먼저 알린다.
5. **계열을 건너는 변환의 목표는 셋이다.** 대상 프로그램(Word·한글)에서 열릴 것, 내용이 빠지지 않을 것, 배치가 깨지지 않을 것.
   쪽 수를 원본과 맞추는 작업은 하지 않는다(ADR 0008 3항). 확인은 실제 프로그램으로 연다(`scripts/word-pages.ps1`·`scripts/hwp-pages.ps1`).

## 대안

| 안 | 버린 이유 |
|---|---|
| 워드 계열에 조판 엔진을 따로 둠 | 계열 사이 어긋남(형식 규칙 차이)은 그대로다. 보기만 6개월~1년이 든다. 같은 계열 보기는 이미 Word 와 3.7% 차이다 |
| 지금대로(모든 저장을 rhwp 모델에서 다시 만듦) | 고치지 않고 저장만 해도 Papy 가 모르는 Word 요소가 빠진다 |
| 계열을 건너는 변환을 없앰 | 사용자가 한글↔워드 변환을 쓴다. 고지하고 사용자가 고르게 하는 편이 낫다 |

## 결과

- `papy-hwp`: DOCX 로 연 문서가 원본을 들고 있다가, 고치지 않았으면 그것을 저장한다(`HwpDocument::original_docx`).
  회귀 테스트는 `unedited_docx_saves_original_bytes`.
- `papy-core`·`papy-render`: 열기 옵션 `rewrite_same_format`(기본 꺼짐). 테스트·`convert_matrix`·`roundtrip_audit` 는 켠다.
- 남은 일: DOCX 부분 쓰기(3항 2단계). [next-steps.md](../development/next-steps.md) 2단계에 있다.
